# 观测构建调整：存活对与零填充 + 设施常驻

## 背景与问题

- 场景为 **一对一拦截**；捕获后 `[_phase_update](marl/MARL_env.py)` 会从 `pairs_realE2P` 中剔除该行，`[UnCapPidNew`/`UnCapEidNew](marl/MARL_env.py)` 仅含存活者。
- `[_positions_full_for_obs](marl/MARL_env.py)` 将紧凑轨迹写回 **全局** `out_p`/`out_e` 时，**未覆盖** 的全局下标仍保留 `PStart_Point`/`Evader` 初值，导致「已拦截成功」的 pid/eid 在观测里仍像存活。
- `[TODCObservationGenerator._build_model_aligned_obs](marl/obs_generator.py)` 已用 `_eid_for_each_pid` 与 `0<=eid<num_e` 控制 `enemy_assigned_`* / `asset_target_`* 的填充，但 **self_uav、self_pts、enemies 全量通道** 仍可能携带初值或无效候选。

## 设计原则

1. **存活集合**：以当前步的 `pairs_realE2P` 为权威（全局 `eid`、`pid` 列），定义：
  - `alive_pids = unique(pairs_realE2P[:, 1])`
  - `alive_eids = unique(pairs_realE2P[:, 0])`
  - 一对一假设下通常每 pid/eid 至多出现一次；若未来有多对，仍以集合为准。
2. **拦截成功后的零填充**：对 **不在 `alive_pids` 的全局 pid**：
  - `self_uav[pid]` → 0；`self_pts[pid]` → 0；`self_pts_mask[pid]` → False（与现有 mask 语义一致）。
  - `ally`_* 中若槽位对应友机 pid ∉ `alive_pids`，不填真实状态（0 + mask False）。
  - 对 **不在 `alive_eids` 的全局 eid**：
    - `enemies[:, eid, :]`、`targets[:, eid, :]` → 0；`enemy_mask[:, eid]`、`target_mask[:, eid]` → False（与「无此敌」一致）。
3. **重要设施一直存在**：
  - `[assets` / `asset_mask](marl/obs_generator.py)` 保持 **始终** 为完整 `value_pos[:, :2]` 与全 True，**不因** 捕获或换目标而置零或删行。
  - `asset_target_self` / `asset_target_per_ally` 仍表示 **当前分配敌机所攻击的设施坐标**（来自 `v_e_nodes` 的 6:8）；无分配或敌已移除时保持 **0 + mask False**，与设施列表分离，避免语义混淆。
4. **攻击目标随敌方变化**（与设施常驻配合）：
  - 当前 `[_build_obs](marl/MARL_env.py)` 传入的 `inferred_targets` 为循环 `ValuePos` 的占位，**未**使用 `[predictLikelyTargetNew](marl/MARL_env.py)` 在 `_compute_isomap_intercept_candidates` 中的结果。
  - 建议在环境中 **缓存** 最近一次重规划得到的每全局 `eid` 推断目标 `(x,y)`（形状 `[num_E, 2]`），在 `_build_obs` 中传入 `obs_generator.generate(..., inferred_targets=cached)`；重规划失败或尚无缓存时回退现有占位逻辑。这样 `v_e_nodes[:, 6:8]` 与「敌方可能更改攻击目标」一致，同时 `assets` 仍完整列出所有设施。

## 观测与模型输入对接（已完成拦截的 pid）

- **目标**：策略网络输入形状仍为 `[num_P, ...]`，但 **已完成拦截、无配对的 pid** 在语义上无效，其「输出」在观测侧应表现为 **无效**，避免网络把旧位置当真值。
- **推荐**：**数值填 0**，并保证 `self_pts_mask` 等 **全部为 False**（与现有 `masked_fill`、MHA `key_padding_mask` 一致）。`[UAVInterceptionNetwork](marl/models.py)` 的 MLP/Attention 对全 mask 行已有 `_apply_mha` 置零行为，**优先不引入 NaN**，以免未处理的线性层产生 NaN 传播。
- **若坚持用 NaN 标记无效**：必须在进入 `enc_*` 之前替换为 0，或改模型首层；需在计划中二选一并写死一处，避免半套实现。
- **训练侧**：`[mappo.py](marl/mappo.py)` / rollout 若仍对全 agent 存 `action_indices`，应对 **无效 pid** 的损失与采样做 mask（或仅对存活 pid 存 logp）；与「全 False 的 `self_pts_mask`」一致时，无效动作分支不应被优化。

## `_apply_assignment_from_action` 与 `pairs_realE2P` 映射

- **现状**：`[_apply_assignment_from_action](marl/MARL_env.py)` 已 `for pid in self.UnCapPidNew` 再取 `action_indices[pid]`；而 `UnCapPidNew` 在 `_phase_update` 中与 `**pairs_realE2P[~Capflag, 1]`** 对齐。
- **计划要求**：显式以 `**pairs_realE2P` 为唯一权威** 做「存活 pid → 候选行」映射（可与 `UnCapPidNew` 等价，但代码路径上优先 `pairs_realE2P[:, 1]` 去重排序，或注释说明二者同源），**仅对这些 pid** 从 `ICFinalActionCandidates` 取子集并应用 `action_indices[pid]`；**无配对的 pid 不参与分配**，其 `action_indices` 条目忽略。
- **可选**：若希望 API 更清晰，可改为 `for (eid, pid) in pairs_realE2P:` 再按 `(eid, pid)` 过滤候选行（与 `_build_c_nodes` 的 pair 键一致），避免仅按 pid 过滤时与一对一场景隐含假设脱节。

## 与训练/网络的衔接

- `[UAVInterceptionNetwork](marl/models.py)` 已依赖 `enemy_self_mask`、`self_pts_mask` 等；零填充后需确认 **全 False 行** 在 MHA 中不产生 NaN（现有 `_apply_mha` 对全 mask 有处理；若某分支全 dead，需与现有实现对齐，必要时在计划中注明做一次 smoke forward）。
- `[mappo.py](marl/mappo.py)` PPO 对死亡智能体若仍采样，需依赖环境 **mask 掉无效动作**（现有 `self_pts_mask`）；零观测与全 mask 候选应一致。

## 风险与边界

- `pairs_realE2P is None` 时（初始化早期）：保持现有报错或显式定义「全未存活」的零观测策略，与 `[_build_c_nodes](marl/obs_generator.py)` 的约束一致。
- 若一步内同时存在「新捕获」与「尚未从 pairs 中移除」的时序问题，应以 **调用 `generate` 时刻** 的 `pairs_realE2P` 为准（与 env step 顺序对齐）。
